## 现在程序怎么运行

```text
main
  ├─ HAL_Init / 时钟 / GPIO
  ├─ USART1 初始化（PA9/PA10，115200）
  ├─ CAN1 硬件初始化（PB8/PB9，500 kbit/s）
  ├─ vcu_app_init
  │    ├─ USART3 CRSF 接收（PB11，420000）
  │    ├─ CAN1 滤波器、接收队列、启动与通知
  │    └─ 控制状态初始化，尝试发送禁用零目标
  └─ while (1)
       └─ HAL 毫秒计数改变时：vcu_app_step(now_ms)
            ├─ CAN 收包、CRSF 解析、ESP32 命令
            ├─ 到控制周期时计算和发送左右电机目标
            └─ 遥测和错误报告
```

TIM7 中断更新 1 ms 计时。默认控制周期 5 ms；主循环不补跑积压的历史节拍。
串口与 CAN 中断继续收数据，主循环消费队列。CAN1 的硬件初始化和协议层启动是两个阶段，
不是两个 CAN 外设。USART1 和 USART3 是两个实际不同的串口。

原有失联检测、中位解锁、故障恢复、调度超时保护、CAN 发送超时和遥测保留。
主循环与中断共用 4 KiB MSP 栈；不再创建任务、不切换 PSP、不使用 FreeRTOS 堆。
FreeRTOS 源文件保留作历史参考，但不参与当前工程构建，CubeMX 中也已关闭 FreeRTOS。
CAN 诊断帧原任务切换次数位置固定为 0，协议格式不变。

## 目标转速（2026-09-16 更新）

VCU 已取消目标转速斜率：遥控混控 → 同步修正 → 限幅/在线检查 → CAN。
加减速由电机控制器处理。旧 RUN 命令的 acceleration 参数仅保留协议兼容，VCU 忽略该值。
STOP、失联、撤销使能及故障保护仍走禁用零目标路径。

## 故障自动恢复（2026-09-16 更新）

CAN 发送失败、控制计算失败和调度超时不再清除运行请求，也不再要求手动 RESET。
故障当次清空目标并尝试发送禁用零目标；后续周期继续检查输入和反馈、重试零目标。
故障消失后，遥控在线、使能有效、控制器反馈正常且油门回中即允许恢复输出，不再等待 500 ms。
回中当次先成功发送禁用零目标，再进入 ARMED，后续控制周期按最新遥控值输出。
零目标发送失败、再次超时、失联或撤销使能时保持停止；油门未回中不能解除保护；转向位置不阻止重新使能。
STOP 命令仍保持停止，只有 RUN 或原有显式 RESET 流程能够恢复运行请求。
电机仍报故障或曾报故障的控制器尚未提供新鲜无故障反馈时，不自动绕过保护。
不自动给电机发送故障复位指令；原有手动 RESET 仍可使用。
历史计数、CAN 错误记录保留；心跳 fault_flags 的 bit5 改为当前 CAN 发送故障，恢复后清除。
公开结构体的 fault_latched 字段仅保留兼容，固定为 false。
此逻辑不适用于 CPU HardFault、Error_Handler 或底层初始化失败，也不修复总线电气错误。
